You are building the backend foundation of a scientific mathematical discovery platform.

IMPORTANT:
This is NOT a normal CRUD SaaS.
The primary goal is to build a reliable scientific computation and experiment engine that can continuously generate, test, validate, store, and retrieve mathematical hypotheses related to Keplerian planetary systems and quantum/hydrogen structure.

Do NOT build the frontend yet.
Do NOT add an LLM yet.
Do NOT generate fake scientific results.
Do NOT claim that any hypothesis is scientifically proven.

==================================================
PHASE 1 — BACKEND FOUNDATION
==================================================

Build a production-oriented Python backend with:

- Python 3.11+
- FastAPI
- PostgreSQL
- SQLAlchemy 2.x
- Alembic
- Pydantic v2
- pytest
- NumPy
- SciPy
- SymPy
- Pint for physical units
- structured logging
- environment-based configuration

The architecture must be modular and designed for future continuous scientific computation.

==================================================
2. DATABASE
==================================================

Configure PostgreSQL through environment variables.

Create the database foundation with SQLAlchemy and Alembic.

At this stage create only the core entities required for the foundation:

- Dataset
- DatasetVersion
- Experiment
- ExperimentRun
- Hypothesis
- Formula
- Result
- Job

Design relationships carefully.

Every experiment and result must be reproducible.

Store:

- UUID primary keys
- created_at
- updated_at
- status
- metadata where appropriate
- version information

Use UTC timestamps.

Never store scientific results only in memory.

==================================================
3. DATA MODEL PRINCIPLES
==================================================

A Dataset must be versioned.

Example:

Dataset:
    TRAPPIST-1

DatasetVersion:
    version 1

If the dataset changes, create a new version instead of silently modifying the old one.

An Experiment must reference an exact DatasetVersion.

An ExperimentRun must reference the exact experiment configuration used.

A Hypothesis must be independently identifiable.

A Formula must preserve both:

1. human-readable mathematical representation
2. machine-readable symbolic representation

Example:

Human:
    sqrt(a / a_ref)

Machine:
    SymPy expression / canonical representation

Do NOT use eval() for mathematical expressions.

==================================================
4. SCIENTIFIC DATA TYPES

Create strongly typed structures for future scientific variables.

At minimum support:

- mass
- length
- time
- energy
- velocity
- momentum
- angular momentum
- eccentricity
- inclination

- orbital period
- dimensionless quantities

Use Pint for dimensional consistency.

The system must distinguish:

    5 meters

from:

    5 dimensionless

Never silently mix incompatible physical units.

==================================================
6. EXPERIMENT REPRODUCIBILITY
==================================================

Every experiment must record:

- dataset version
- hypothesis/formula
- input configuration
- random seed if randomness is used
- software version
- experiment status
- start time
- end time
- result metadata

The same experiment configuration should be reproducible.

Do not use uncontrolled randomness.

==================================================
7. JOB FOUNDATION
==================================================

Create the foundation for long-running scientific jobs.

A Job should have states such as:

PENDING
RUNNING
COMPLETED
FAILED
CANCELLED

Store:

- job id
- experiment id
- status
- attempts
- started_at
- finished_at
- error information
- heartbeat information

Do NOT build the full worker system yet.

But design the models so Phase 5 can implement persistent workers, retries, checkpoints, and crash recovery.

API errors should return useful structured responses.

Internal logs must contain enough information to diagnose failures.

Never expose secrets.

==================================================
13. SCIENTIFIC INTEGRITY RULES
==================================================

These rules are mandatory:

1. Never fabricate experimental results.
2. Never modify test data based on results.
3. Never tune a formula using the test set.
4. Never label a candidate equation as a scientific law automatically.
5. Keep training, validation, and test data logically separate.
6. Preserve experiment history.
7. Preserve failed experiments.
8. Never overwrite previous scientific results.
9. All formulas must be reproducible.
10. All future discovery algorithms must produce auditable experiment records.
